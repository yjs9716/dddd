# 오픈소스 CFD 연습 케이스: 직선 유로 냉각판

FreeCAD → Gmsh → OpenFOAM → 후처리까지 **한 번에 자동으로 도는 가장 단순한 예제**입니다.
외부망 연습용입니다. **사내 형상·치수·물성은 넣지 마세요.**

```
알루미늄 판 100 x 40 x 8 mm
 ┌──────────────────────────────────────┐
 │  ════════ 유로 6 x 3 mm ═══════════▶ │   PAO 근사 유체 0.5 L/min, 입구 27 °C
 └──────────────[ 발열 20 W ]───────────┘   밑면 중앙 20 x 20 mm
```

---

## 1. 폴더 구성

| 파일 | 역할 |
|---|---|
| `params.json` | 설계변수와 조건 (치수 mm, 발열량 W, 유량 L/min, 입구온도 K, 격자 크기 mm) |
| `make_geom.py` | **[1단계] FreeCAD**: Spreadsheet에 변수를 넣고 형상 생성 → `solid.step`, `fluid.step`, `coldplate.FCStd` |
| `make_mesh.py` | **[2단계] Gmsh**: 고체·유체 접촉면 공유, 발열 패드 면 분할, 이름 지정, 사면체 격자 → `coldplate.msh` |
| `case_template/` | **[3단계] OpenFOAM** 케이스 원본 (경계조건, 물성, 해석 설정, `Allrun`) |
| `post.py` | **[4단계] 후처리**: 최고 온도, 압력강하, 열수지, 수렴 확인 |
| `run_case.py` | 1~4단계를 한 설계점에 대해 순서대로 실행 |
| `sweep.py` | **[5단계]** DOE 표(`doe_example.csv`)의 설계점을 차례로 실행 → `sweep_results.csv` |

해석 결과(`runs/`)는 `.gitignore`로 제외되어 있습니다. 스크립트로 언제든 다시 만들 수 있습니다.

## 2. 설치 (Ubuntu 22.04/24.04 또는 Windows WSL2)

### OpenFOAM (ESI 판 v2412)
```bash
curl -s https://dl.openfoam.com/add-debian-repo.sh | sudo bash
sudo apt-get install -y openfoam2412-default
# 사용할 때마다 (또는 ~/.bashrc에 추가)
source /usr/lib/openfoam/openfoam2412/etc/bashrc
```

### Gmsh (Python API)
```bash
sudo apt-get install -y libglu1-mesa libxcursor1 libxinerama1 libxft2
pip install gmsh
```

### FreeCAD 1.x
- 방법 A: 공식 AppImage를 받아 `--appimage-extract` 한 뒤 `squashfs-root/usr/bin/freecadcmd` 사용
- 방법 B: conda (`micromamba create -n fc -c conda-forge freecad`)

`freecadcmd` 경로를 환경 변수로 알려주세요.
```bash
export FREECADCMD=/path/to/freecadcmd
```

> 참고: 이 예제는 conda-forge의 OpenFOAM v2412, FreeCAD 1.1.3, gmsh 4.15로 검증했습니다.
> conda 판 OpenFOAM은 MPI 없이 빌드되어 병렬 실행이 안 됐습니다.
> 병렬(`--np 4`)을 쓰려면 위의 공식 deb 설치를 권장합니다.

## 3. 실행

```bash
source /usr/lib/openfoam/openfoam2412/etc/bashrc
export FREECADCMD=/path/to/freecadcmd
cd openfoam_practice

python run_case.py              # 직렬 실행
python run_case.py --np 4       # 병렬 실행 (MPI 있는 OpenFOAM)
```

진행 표시:
```
[geom] ... OK
[mesh] ... OK
[solve] ... OK
=========== 결과 요약 ===========
 ...
```

각 단계 로그는 `runs/case_000/` 안에 있습니다.
- `run.geom.log`, `run.mesh.log`, `run.solve.log` : 단계별 전체 출력
- `log.gmshToFoam`, `log.splitMeshRegions`, `log.checkMesh.*`, `log.chtMultiRegionSimpleFoam` : OpenFOAM 로그

### 결과 확인 (ParaView)
```bash
cd runs/case_000
touch case.foam
paraview case.foam
```
왼쪽 Properties에서 **Mesh Regions**에 `fluid/internalMesh`, `solid/internalMesh`를 체크하고 Apply.
T(온도), U(속도)를 색으로 보고, Slice 필터로 단면을 잘라보세요.

### 여러 설계점 돌리기
```bash
python sweep.py doe_example.csv
```
`doe_example.csv`의 열 이름은 `params.json`의 키와 같아야 합니다. 없는 키는 기본값을 씁니다.
중간에 멈춰도 다시 실행하면 끝난 케이스는 건너뜁니다.

## 4. 결과 보는 법

| 항목 | 의미 | 확인 기준 |
|---|---|---|
| 고체 최고 온도 | 목적함수 1 | - |
| 압력강하 | 목적함수 2 (입구 평균 압력 - 출구) | - |
| 열수지 오차 | (유체가 가져간 열 - 발열량) / 발열량 | **±2 % 이내** |
| 마지막 10 % 구간 변동 | 수렴 여부 | 최고 온도 < 0.01 K, 압력강하 < 0.1 % |

손으로 확인하는 값 (기본 조건):
- 질량유량 = 800 × 0.5/60000 = 6.67×10⁻³ kg/s
- 유체 온도 상승 = 20 / (6.67×10⁻³ × 2200) ≈ **1.36 K**
- 레이놀즈 수 ≈ 185 → 층류

## 5. 다음에 해볼 것 (순서대로)

1. **값 바꿔보기**: `params.json`에서 `ch_w`, `flow_Lpm`, `Q_heater_W`를 바꿔 결과가 예상대로 변하는지 확인
2. **격자 독립성**: `mesh_min`을 0.6 → 0.4 → 0.28 (약 1.4배씩)로 바꿔 최고 온도와 압력강하가 수렴하는지 확인. 세 결과로 GCI 계산
3. **FreeCAD GUI로 열어보기**: `runs/case_000/coldplate.FCStd`를 열고 Spreadsheet 값을 바꾸면 형상이 따라 바뀌는 것 확인
4. **sweep 돌려보기**: `doe_example.csv`에 행을 추가해 자동 반복 확인
5. **형상 확장**: 유로를 2패스(U턴)나 분기 형태로 바꾸기. `make_geom.py`의 형상 부분과 `make_mesh.py`의 입출구 찾는 부분만 고치면 됨

## 6. 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| `GEOM_FAIL: ... wall` | 벽 두께가 0.5 mm보다 얇음. `ch_z`, `ch_h`, `ch_w` 조합 확인 |
| FreeCAD `Invalid alias` | alias에 단위 이름(L, W, H, m 등)은 못 씀. 그래서 `plate_L`처럼 접두어를 붙였음 |
| gmsh `libGLU.so.1` 없음 | `sudo apt-get install libglu1-mesa` |
| `MESH_FAIL: inlet/outlet ... not found` | 입출구 면이 x=0, x=L 평면에 있어야 함. 형상을 바꿨다면 `make_mesh.py`의 면 찾기 부분 수정 |
| `cannot find file ".../constant/g"` | v2412는 `g`를 `constant/` 바로 아래에서 읽음 (region 폴더 아님) |
| `cannot find file ".../system/fluid/decomposeParDict"` | 병렬 실행 시 region별 사본 필요. `Allrun`이 자동 복사함 |
| `The dummy Pstream library cannot be used in parallel mode` | MPI 없이 빌드된 OpenFOAM. 직렬로 돌리거나 공식 deb 판 설치 |
| 발산 (`Floating point exception`) | `system/fluid/fvSolution`의 완화계수 낮추기 (U 0.3 → 0.2, p_rgh 0.7 → 0.3) |
| 열수지 오차가 큼 | 반복 수 부족(`controlDict`의 `endTime` 늘리기) 또는 경계조건 확인. 출구 온도는 반드시 `weightedAverage`(질량가중)로 계산. `weightedAreaAverage`로 하면 면적이 한 번 더 곱해져 이 예제에서 약 7 % 틀림 |
| 시간 폴더가 수백 개 생김 | `wallHeatFlux` 같은 기능이 필드를 저장하면서 폴더를 만듦. `writeControl writeTime;`으로 설정 |
| 결과가 1000배 이상함 | 단위 문제. `make_mesh.py`의 `OCCTargetUnit = "M"` 확인, `checkMesh` 로그의 bounding box 확인 |

## 7. 이 예제의 단순화 (실제 해석과 다른 점)

- 유체 물성이 **상수**입니다. 실제 PAO는 점도가 온도에 따라 크게 변하므로 다항식 물성으로 바꿔야 합니다.
- 판 외부면은 **단열**입니다. 실제로는 대류·복사 조건을 줄 수 있습니다.
- 격자가 **사면체만** 있고 벽면 경계층(프리즘) 격자가 없습니다. 벽 근처를 촘촘하게 해서 보완했지만, 정밀 해석에서는 격자 독립성 확인이 필수입니다.
- 입구 속도가 **균일 분포**입니다. 입구 쪽 일부 구간은 유동이 발달하는 중입니다.
